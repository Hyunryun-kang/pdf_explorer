# 오프라인 PDF 내용 검색기(Windows GUI)

- 요구사항 문서 생성 일시: 2026-03-03

## 1. 목표
PC(Windows)에 저장된 PDF 파일들의 내용을 인터넷 없이(offline) 읽고, 사용자가 입력한 키워드/구문을 빠르게 검색하여 결과(파일명 + 페이지 번호)를 제공하는 GUI 데스크톱 프로그램을 만든다.

## 2. 범위(확정)
- 실행 환경: Windows
- 형태: GUI 데스크톱 앱
- 대상 선택: 폴더 선택 후 하위 폴더까지 재귀적으로 PDF 수집
- PDF 유형: 텍스트 PDF(선택 가능한 텍스트) 위주
- 언어: 한국어
- 규모: 중규모(수백 개 PDF)
- 업데이트 반영: 증분 인덱싱(변경된 파일만 재색인)

## 3. 핵심 기능 요구사항
### 3.1 인덱싱(색인)
- 사용자가 지정한 폴더(재귀)에서 PDF를 탐색한다.
- PDF를 페이지 단위로 텍스트를 추출하여 로컬 DB에 저장한다.
- 변경 감지: `파일 경로 + 수정시간 + 크기`(또는 해시)를 저장하여 변경 여부를 판단한다.
- 삭제/이동 반영: 폴더 재스캔 결과와 DB를 비교하여 삭제된 파일의 인덱스를 제거하고, 이동/경로 변경은 재등록(또는 동일 파일 판별 시 경로 갱신)한다.
- 인덱싱은 UI를 블로킹하지 않고 백그라운드로 동작해야 한다.
- 인덱싱 진행률(최소: 파일 단위)을 표시하고, 취소 및 오류 목록을 제공한다.

### 3.2 검색
- 기본: 키워드/구문 포함 검색을 제공한다.
- 확장: 유사어/관련어 확장 검색을 제공한다.
  - 기본 구현: 사용자 편집 가능한 동의어 사전(예: JSON 또는 SQLite 테이블)로 질의어를 확장하여 OR 조건으로 검색한다.
  - UI에서 확장 검색 on/off를 토글할 수 있어야 한다.
  - 확장 규칙: 중복 제거, 순환(예: A->B, B->A) 방지.

### 3.3 결과
- 검색 결과는 최소 `파일명 + 페이지 번호`를 표시한다.
- (옵션) 결과 스니펫(일부 문장/문단 미리보기)을 제공할 수 있다.
- 결과 클릭 시 PDF를 열 수 있어야 한다.
  - 기본안: OS 기본 PDF 뷰어 호출
  - 제약: 뷰어별 페이지 점프(`file.pdf#page=N` 등) 지원이 다르므로, 지원 여부를 문서화한다.
  - 대안(옵션): 내장 뷰어(WebView2/PDFium 등)를 Phase 2로 고려한다.

## 4. 품질/제약(리스크 포함)
- 완전 오프라인 동작(네트워크 의존성 없음).
- 한국어 검색 품질 리스크:
  - 기본안: SQLite FTS5의 `unicode61` 토크나이저(공백 기반)로 시작한다.
  - 품질 요구가 높을 경우: N-gram 기반 인덱싱 또는 커스텀 토크나이저/외부 라이브러리 도입을 옵션으로 둔다.
- 텍스트 추출 라이브러리는 배포/라이선스 영향을 고려해 선정한다.

## 5. 데이터/저장 설계(제안)
- 로컬 DB: SQLite
- 테이블(예시)
  - documents: doc_id, path(unique), file_mtime, file_size, last_indexed_at, status
  - pages: doc_id, page_no, text
  - synonyms: term, synonym (사용자 사전)
- 검색 인덱스: SQLite FTS5(페이지 단위 전문검색)
- 랭킹: BM25(FTS 기본) 또는 단순 일치 우선 정렬(요구에 따라 조정)

## 7. 플랜 완료 시 기대 결과
- 사용자는 Windows에서 오프라인으로 폴더 내(재귀) PDF를 인덱싱하고, 한국어 키워드 검색 및 동의어 확장 검색으로 빠르게 관련 페이지(파일명+페이지 번호)를 찾을 수 있다.
